# 会话图片 413 修复实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修复 QQ bot 长会话中 base64 图片累积导致服务商网关 413 Request Entity Too Large 的问题：历史图片"用过即弃"降级为文本占位符（方案 1），并让网关 HTML 错误页显示为友好提示（方案 3）。方案 2（read 图片前压缩）留待后续计划。

**Architecture:** 图片消息在"成功发送给 LLM 一次"之后，立即从会话历史中降级为文本占位符（保留文本部分、丢弃 base64），这样每张图片只在紧跟其后的一次调用中出现，请求体不再随轮次线性膨胀。降级挂在 `run_one_step` 的 token 校准块之后——校准基于"实际发送的内容"，降级后估算只会偏高（安全方向）。错误友好化挂在 `LlmError::from_openai_error` 的 `JSONDeserialize` 分支：检测以 `<` 开头的 HTML 载荷，提取 `<title>`，映射为新变体 `GatewayError`（沿用 7147824 内容审核友好提示的同一模式）。

**Tech Stack:** Rust（`crates/robit-agent`、`crates/robit-ai`），`async-openai` 类型，`thiserror`，现有 `cargo test` 单元测试。

**Spec:** 2026-09-28 日志分析（本会话）：`.robit/logs/robit-2026-09-28.log` 18:09:13 起连续两次 `413 Request Entity Too Large`（openresty HTML 错误页被 async-openai 包装成 `JSONDeserialize` 错误）。根因：`read` 工具对 PNG 做 base64 编码注入历史（`read.rs:79-91`），`agent.rs:1037-1044` 把整批图片作为独立 user 消息 push 进历史且永不清理，14 张 2K PNG 的 base64 累积到几十 MB，超出网关请求体限制；token 估算只算文本（46.5k < 91.7k 阈值），截断永不触发。

## 历史兼容性说明（升级路径已验证）

图片消息**从不持久化**，因此升级无迁移问题：

- DB `messages` 表只有 `content TEXT`（`storage.rs:273`），chatbot/GUI 前端保存的都是纯文本（`frontend.rs:117/140`、`commands.rs:154`）。agent 注入的图片 user 消息（`build_image_user_message` / `build_multimodal_message` 产物）只存在于内存 `session.history`。
- **当前 413 出错的会话升级重启后可正常加载**：重启后 `load_chat_messages` 从 DB 重建纯文本历史（`message_to_chat_message` 的 user 分支固定产出 `Text` 内容，`storage.rs:694`），没有任何 base64，请求体恢复正常——事故会话无需清理即自愈。
- `downgrade_history_images` 只把内存中的 `Array` 内容换成 `Text`，不改变消息数量/角色/DB 记录，与 DB 重载后的消息形态一致。
- `sanitize_history_for_model` 继续兜底 `supports_images=false` 的场景（模型切换、历史不含图片时是 no-op），与降级逻辑互不干扰。

## Review Focus

1. **图片消息只有图片 part、没有文本 part**（如空文本构造的 data_url 消息）——降级后 content 应仍有占位文本，不能变成空字符串。
2. **降级与校准的顺序**——校准必须基于"实际发送的带图片历史"；降级发生在校准之后、push assistant 消息之前，保证 `snapshot_message_count`/`last_known_prompt_tokens` 语义不被破坏。
3. **JSON 解析失败的非 HTML 载荷**（如 `"not json at all"`）——必须继续走原有 `OpenAiError` 透传路径，不能被误判为网关错误。
4. **HTML 无 `<title>` 或 `<title>` 含中文**——提取不得 panic（字节边界安全），无 title 时使用兜底文案。
5. **幂等性**——同一历史重复调用降级函数第二次必须返回 0（不重复追加占位说明）。

```rust
/// Downgrade image content in session history to text placeholders.
///
/// Base64 images injected into history (tool-result images, user
/// attachments) are re-sent on EVERY LLM call. A session that reads many
/// multi-MB images quickly exceeds the provider gateway's request body
/// limit (HTTP 413 "Request Entity Too Large") even though the token
/// estimate stays low — providers count ~1k tokens per image regardless
/// of byte size, so token-based truncation never fires.
///
/// After a successful LLM call the model has already seen the images, so
/// they are replaced with a text note. Images added by later tool calls
/// still get sent on the next call (one-shot delivery).
fn downgrade_history_images(history: &mut Vec<ChatCompletionRequestMessage>) -> usize {
    let mut downgraded = 0usize;
    for msg in history.iter_mut() {
        if let ChatCompletionRequestMessage::User(user_msg) = msg {
            if let ChatCompletionRequestUserMessageContent::Array(parts) = &user_msg.content {
                let image_count = parts
                    .iter()
                    .filter(|p| {
                        matches!(
                            p,
                            ChatCompletionRequestUserMessageContentPart::ImageUrl(_)
                        )
                    })
                    .count();
                if image_count > 0 {
                    let mut text: String = parts
                        .iter()
                        .filter_map(|p| {
                            if let ChatCompletionRequestUserMessageContentPart::Text(t) = p {
                                Some(t.text.as_str())
                            } else {
                                None
                            }
                        })
                        .collect::<Vec<_>>()
                        .join("\n");
                    if !text.is_empty() {
                        text.push('\n');
                    }
                    text.push_str(&format!(
                        "[历史图片已省略：{image_count} 张图片已发送给模型，为控制请求体积不再重复发送]"
                    ));
                    user_msg.content = ChatCompletionRequestUserMessageContent::Text(text);
                    downgraded += 1;
                }
            }
        }
    }

    if downgraded > 0 {
        tracing::info!(
            "downgrade_history_images: replaced {} image message(s) with text placeholders \
             (images are sent once, then dropped to keep request bodies small)",
            downgraded
        );
    }
    downgraded
}
```

在 `run_one_step` 中、token 校准块（`tracing::trace!("Token calibration updated: ...)` 之后，`// Add assistant message to history` 之前，约 753-755 行之间）插入：

```rust
        // what was actually sent, so later estimates only over-count, which
        // is the safe direction for truncation.

```

```rust
/// Detect a reverse-proxy HTML error page (e.g. openresty "413 Request
/// Entity Too Large") in a raw payload that failed JSON deserialization,
/// and turn it into a friendly error. Proxies answer with HTML instead of
/// JSON, which async-openai can only surface as a deserialization failure.
fn extract_gateway_error(raw: &str) -> Option<LlmError> {
    if !raw.trim_start().starts_with('<') {
        return None;
    }
    let title = extract_html_title(raw).unwrap_or_else(|| "未知网关错误".to_string());
    let hint = if title.contains("413") {
        "请求体过大，通常是上下文中图片过多或过大导致，建议减少读取图片或新建会话（/new）后重试".to_string()
    } else {
        "请求被服务商网关拒绝，请稍后重试或检查服务商状态".to_string()
    };
    Some(LlmError::GatewayError { title, hint })
}

/// Extract the `<title>` text from an HTML error page. `<title>`/`</title>`
/// are ASCII markers, so the byte offsets from `find` are always valid UTF-8
/// boundaries and slicing cannot panic.
fn extract_html_title(raw: &str) -> Option<String> {
    let start = raw.find("<title>")? + "<title>".len();
    let end = raw[start..].find("</title>")? + start;
    let title = raw[start..end].trim();
    if title.is_empty() {
        None
    } else {
        Some(title.to_string())
    }
}
```

注：`extract_html_title` 对空 title 返回 `None`，由 `extract_gateway_error` 的 `unwrap_or_else` 兜底为"未知网关错误"，满足 `html_without_title_falls_back_to_generic_title`。
